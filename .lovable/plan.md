# ทำไมสลิปใบเดียวกันถูกบันทึก 2 รอบ และควรทำงานแบบไหน

## สาเหตุที่เกิดขึ้นจริง (ตรวจแล้วในระบบ)

ตอนกดจ่ายเงิน+แนบสลิป ระบบสร้างรายการค่าใช้จ่ายให้โดย
- ใช้ **ยอดเต็ม (ก่อนหัก ณ ที่จ่าย)** เป็นยอดของรายการ
- ใช้ **วันที่กดจ่ายวันนี้** ไม่ใช่วันที่บนสลิป
- **ไม่มีเลขอ้างอิงจากสลิป** เพราะยังไม่ได้อ่านสลิป

พอส่งสลิปใบเดียวกันเข้าไลน์ ตัวกันซ้ำของไลน์เทียบ 2 อย่างคือ เลขอ้างอิงบนสลิป และ ยอด+วันที่+เวลา
รายการที่สร้างจากการกดจ่ายไม่ตรงทั้งสองแบบ (ยอดเป็นยอดเต็มไม่ใช่ยอดโอน วันที่เป็นวันนี้ไม่ใช่วันบนสลิป)
จึงถือว่าเป็นสลิปใหม่และบันทึกเพิ่มอีกรายการ

## คำตอบสำหรับคำถาม

วันนี้ยังไม่ควรทำทั้งสองทางกับสลิปใบเดียวกัน ให้เลือกทางเดียว
- ถ้าเป็นบิลคู่ค้า/ใบเบิกทีมงานที่อนุมัติและเตรียมจ่ายไว้แล้ว → **แนบตอนกดจ่ายทางเว็บทางเดียว ไม่ต้องส่งเข้าไลน์อีก**
- ถ้าเป็นค่าใช้จ่ายทั่วไปที่ไม่มีใบเบิกรออยู่ → **ส่งเข้าไลน์ หรืออัปโหลดเป็นชุด**

ส่วนที่อยากได้คือ "ส่งทุกใบเข้าไลน์แล้วให้จับคู่กับใบเบิกที่เตรียมจ่ายไว้เอง" ปัจจุบันทำได้บางกรณีเท่านั้น
(จับคู่ใบเบิกทีมงานจากเลขบัญชี/ยอดโอน และตัดจ่ายบิลด้วยรหัส `@B####`/`@P####` ในบันทึกช่วยจำ)
แต่ยังไม่ครอบคลุมกรณีที่แนบสลิปทางเว็บไปก่อนแล้ว

## สิ่งที่จะแก้ให้ปลอดภัยทั้งสองทาง

1. เทียบสลิปซ้ำเพิ่ม 2 เงื่อนไข
   - เทียบ **ยอดโอนจริง** (ยอดเต็มลบหัก ณ ที่จ่าย) ไม่ใช่เฉพาะยอดเต็ม
   - ขยายช่วงวันที่เทียบเป็น ±7 วัน สำหรับรายการที่สร้างจากการกดจ่าย (ซึ่งลงวันที่เป็นวันกดจ่าย)
2. ถ้าเจอว่าตรงกับรายการที่มีอยู่แล้วและรายการนั้น **ยังไม่มีไฟล์สลิป** → เอาสลิปจากไลน์ไปเติมให้รายการเดิม
   พร้อมเก็บวันที่จริงบนสลิปและเลขอ้างอิง แทนการสร้างรายการใหม่ แล้วตอบกลับทางไลน์ว่า "เติมสลิปให้รายการเดิมแล้ว"
3. ถ้ารายการเดิมมีสลิปอยู่แล้ว → ตอบกลับว่าซ้ำ ไม่บันทึกใหม่ (พฤติกรรมเดิม แต่จะจับได้จริงแล้ว)
4. ตอนกดจ่าย+แนบสลิปทางเว็บ จะเก็บ **ยอดโอนจริง** ไว้ในรายการด้วย เพื่อให้ระบบเทียบสลิปได้ตรงในอนาคต
5. เพิ่มข้อความแนะนำสั้นๆ ในหน้าเตรียมจ่าย ว่าถ้าแนบสลิปที่นี่แล้วไม่ต้องส่งเข้าไลน์ซ้ำ (ถ้าส่งก็ไม่เสียหาย ระบบจะรวมให้)
6. เพิ่มปุ่มใน "ตรวจรายการซ้ำ" ให้รวมคู่ที่เป็นยอดเต็มกับยอดโอนของสลิปใบเดียวกันได้ เพื่อเก็บกวาดรายการซ้ำที่เกิดขึ้นแล้ว

## รายละเอียดทางเทคนิค

- แก้ตัวกันซ้ำใน `supabase/functions/line-webhook/index.ts` (บล็อกราว บรรทัด 1472-1520): เพิ่มการค้นหาโดยเทียบ `amount` และ `amount - wht_amount` กับยอดบนสลิป ในช่วง `expense_date` ±7 วัน และเงื่อนไข `receipt_url is null` เพื่อเติมสลิปแทนการ insert
- ใช้ `expenses.ocr_date_raw`, `transaction_id`, `expense_time` เดิมในการอัปเดตรายการที่จับคู่ได้ ไม่แตะทริกเกอร์ `trg_validate_expense_date` / `trg_zz_flag_expense_date` / ทริกเกอร์เก็บประวัติการลบ
- `src/pages/PaymentQueue.tsx` (insert รายการค่าใช้จ่ายราว บรรทัด 211 และ 430): เพิ่มการเก็บยอดโอนจริงลง `memo_text`/ฟิลด์ที่มีอยู่ ไม่เพิ่มคอลัมน์ใหม่ถ้าไม่จำเป็น
- ไม่เรียก FlowAccount API และไม่แก้สคีมาส่วนที่ป้องกันไว้
